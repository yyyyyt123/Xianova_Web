### 5.1 数据库实施明细

本阶段先采用 MySQL 8.0.36、InnoDB、显式 utf8mb4 / utf8mb4_0900_ai_ci，沿用 Asia/Shanghai 时间约定。当前库默认是 utf8mb3，不能依赖默认值创建新表；不修改原库或已有表的字符集。

| 设计项 | 实施与验证 |
| --- | --- |
| 连接与基线 | 使用已提供的开发连接，通过独立受控配置加载密码；先检查现有结构及迁移历史。此次只读发现无 flyway_schema_history，不能直接对该库 migrate。 |
| 实体字段 | 与 SQL 草案四表共 95 个字段逐项对应；主键 Long 对外按字符串，操作人引用 user.uid，候选人不创建登录账号。 |
| JSON | 为草稿、发布、岗位及告知快照配置可靠 TypeHandler 或等效映射；验证 Unicode、结构版本、512 KiB 岗位内容上限和回读一致性。 |
| 公开投影 | 发布事务同步 published_payload、published_*、发布版本和审计；草稿更新不得改公开查询投影。 |
| 幂等与补传 | 唯一键冲突回查并验证 token 和指纹；初次指纹不因新附件改变，尝试序号在申请行锁内预留。 |
| 发送隔离 | 当前 attempt_id 和 row_version 参与条件更新，避免旧回调覆盖结果；SMTP 在提交事务后执行。 |
| 清理 | 手工和到期清理物理删除申请及全部通知，追加不含候选人正文的审计；先处理活动发送，不留孤儿记录。 |
| 备份恢复 | 删除凭据至少覆盖 30 天备份窗口，且来源不随本次恢复回退；恢复先重放删除再开放个人资料查询。 |
| 查询性能 | 用 EXPLAIN 验证发布排序、岗位筛选、联系信息精确查找和到期批次；不声称姓名 contains 可利用普通前缀索引。 |
| 备注 | 表、全部字段的 COMMENT 以及索引用途统一用中文；英文只用于程序标识、枚举和必要技术名称。 |

`schema_draft.sql` 是设计附件，不是已应用的 Flyway 迁移。已按用户授权在开发库仅执行这四张新表的建表语句；新增Flyway文件已保存，未执行整库baseline/migrate。
