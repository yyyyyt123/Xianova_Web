| 页面 | 路由 | 内容与行为 |
| --- | --- | --- |
| 导航入口 | 现有 Header | 增加“加入我们”，沿用现有导航样式、当前页状态和移动端交互。 |
| 岗位列表 | `/[locale]/careers` | 展示开放岗位；无岗位时显示空状态。 |

| 申请页面 | `/[locale]/careers/[jobId]/apply` | 展示所选岗位、申请表、简历上传、告知确认与提交结果。 |

页面使用现有布局、语言导航、字体和组件风格，适配桌面与手机。UI 文案提供中英文；正式 JD 的语言版本由 HR 提供和确认，不能把临时翻译当作已审核招聘内容上线。

### 3.2 岗位数据

每个岗位至少包含：稳定岗位编号、名称、工作地点、岗位类别、招聘类型、职责、任职要求和开放状态。

首期建议由 HR 提供内容、开发维护配置并发布，不建设岗位管理后台。前端展示和后端提交校验必须使用一致的岗位编号与开放状态；具体采用共享配置还是后端只读岗位接口，开发前定稿。

- 详情必须与申请页的岗位相对应。
- 岗位关闭后禁用申请，提交接口再次校验。
- 无效岗位显示不存在或停止招聘提示。
- 申请入库保存岗位名称及必要版本快照，后续 JD 变更不改写历史申请。

### 3.3 申请字段建议

以下字段是可实施的首期建议，最终必填项由 HR 确认。

| 字段 | 建议要求 | 说明 |
| --- | --- | --- |
| 应聘岗位 | 必填，自动带入 | 服务端根据 `jobId` 获取可信岗位信息。 |
| 姓名 | 必填 | 去除首尾空白，设置长度限制。 |
| 邮箱 | 必填 | 格式校验，用作邮件回复地址。 |
| 手机号与区号 | 建议必填，待确认 | 不将所有号码限定为中国大陆格式。 |
| 简历 | 必填 | 单文件，首期建议 PDF / DOCX；文件大小上限待确认。 |
| 补充说明 | 选填 | 可填写项目或作品链接，设置长度限制。 |
| 隐私告知确认 | 必填 | 用户主动勾选，记录告知版本，不预选。 |

截图中的最高学历、开始工作时间、招聘渠道和真实性声明是否加入，均待 HR 确认。邮箱不重复收集；真实性声明不能代替招聘隐私告知。

### 3.4 交互要求

- 上传区域明确显示支持格式和大小；选中文件后显示文件名，可删除、更换。
- 对字段使用标签、必填标识和就近错误提示，支持键盘操作。
- 提交中防止双击；失败保留已填文本，必要时提示重新选择文件。
- 前端限制只用于体验，服务端必须重新校验。
- 不显示“已上传并自动解析”等未实现的提示。
- 投递结果明确区分“申请已登记”和“简历邮件已被发信服务器受理”。

## 4. 申请流程与异常

### 4.1 正常流程

1. 候选人从岗位详情进入申请页，填写信息、选择简历、确认告知。
2. 浏览器以 `multipart/form-data` 直接请求 Java 后端招聘接口。
3. 后端执行限流、字段校验、岗位校验、文件大小和文件类型校验。
4. 在数据库事务内保存申请和初始通知记录，并提交事务。
5. 在事务外使用招聘独立 SMTP 客户端发送邮件和附件。
6. 更新发送状态，返回申请编号、请求编号及投递结果。
7. 清理临时文件；异常退出遗留文件由受控清理任务处理。

### 4.2 结果与页面行为

| 情况 | 页面表达 | 数据及后续处理 |
| --- | --- | --- |
| 字段或文件无效 | 提示具体原因 | 不创建有效申请；保留表单。 |
| 岗位关闭 | 该岗位已停止招聘 | 拒绝提交，提供返回岗位列表入口。 |
| 入库失败 | 提交未完成，请稍后重试 | 不显示登记成功，不继续发送邮件。 |
| 已登记，SMTP 已受理 | 申请已提交，请保存申请编号 | 不承诺 HR 已阅读或一定进入收件箱。 |
| 已登记，明确发信失败 | 申请已登记，简历邮件投递未完成 | 保留记录，给出关联原申请的重试或补传方式。 |
| 网络超时、发信结果未知 | 暂时无法确认投递结果 | 保留提交标识，核对原结果后再处理。 |
| 触发限流 | 操作过于频繁，请稍后重试 | 读取重试等待时间，保留表单。 |

### 4.3 不长期保存简历的限制

应聘记录入库不代表数据库保存了简历。邮件失败且临时文件已清理、或进程重启丢失临时文件时，系统不能自动恢复完整附件邮件，需要候选人重新上传或通过备用邮箱补投。

首期不承诺跨重启后的附件自动重试。备用投递邮箱、补传入口的具体交互、异常申请处理人待确定。异常处理能力必须在上线前具备，不能把发信失败显示成完整投递成功。

### 4.4 幂等与补传

- 同次申请使用高随机性幂等标识，数据库唯一约束防止重复创建申请。
- 请求内容不一致却复用同一标识时，拒绝覆盖原申请。
- 已确认 SMTP 受理的申请，重复请求返回原结果，不再次发信。
- 只有原申请持有者可以使用受控凭据补传；不可仅凭申请编号触发发信或查看个人信息。
- `UNKNOWN` 状态不能盲目自动重发。SMTP 超时可能发生在服务器已受理之后，无法仅靠本地状态承诺邮件绝不重复。
- 具体采用签名重试令牌或等效机制，在接口开发前定稿。

## 5. 后端接口

### 5.1 边界

建议新增模块 `xianova_recruitment`，核心接口：

```text
POST /api/xianova/recruitment/applications
Content-Type: multipart/form-data
```

该路径是建议契约，尚未实现。仅申请提交匿名开放；内部记录查询复用后台鉴权，并限制授权范围。首期不开放匿名申请列表和任意文件下载接口。

### 5.2 请求字段建议

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `jobId` | string | 必填，校验开放岗位。 |
| `name` | string | 必填，长度与字符校验。 |
| `email` | string | 必填，邮箱格式校验。 |
| `phoneCountryCode` / `phone` | string | 是否必填待确认，服务端统一规范。 |
| `message` | string | 选填，限制长度。 |
| `resume` | file | 必填，单文件；允许类型与大小待确认。 |
| `privacyAccepted` | boolean | 必须为 true；multipart 使用约定的序列化格式。 |
| `privacyVersion` | string | 对应有效招聘告知文本。 |
| `idempotencyKey` | string | 必填，同次重试复用，站点内唯一。 |

`siteCode=xianova` 和业务类型由后端固定，不能信任前端决定邮件路由。请求不接受 SMTP 凭据、发件人、收件人和任意外部附件 URL。

### 5.3 响应与错误

已入库响应至少包含 `applicationId`、`requestId`、`submissionStatus`、`emailStatus` 和可操作提示。明确区分登记成功与通知成功，不能把布尔 `success` 当作唯一状态。

建议状态码：首次登记 `201`，幂等返回 `200`，字段无效 `400`，岗位关闭或标识冲突 `409`，超大请求 `413`，不支持类型 `415`，限流 `429`，未入库的服务不可用 `503`。已入库但发信失败，应返回原申请编号和准确邮件状态。

读取岗位、内部查询、受控补传的接口或复用方式在技术定稿时补齐，不能在缺少权限设计的情况下增加公开状态查询。

## 6. 邮箱配置隔离

### 6.1 原有业务必须继续工作

以下配置继续服务原业务，不被招聘配置覆盖：

- `spring.mail`、`CONTACT_SMTP_*`、`CONTACT_EMAIL_*`。
- 原 `contact-mail.env` 的加载与用途。
- 原 `EmailContactNotificationClient`、收件人及飞书通知目标。
- 原 `/api/contact/messages` 的请求与结果语义。

### 6.2 招聘独立客户端

新建招聘专用配置对象和邮件服务封装，其内部持有独立 SMTP 客户端，避免直接新增全局 `JavaMailSender` / `MailSender` Bean。

原因：旧模块通过 `ObjectProvider<JavaMailSender>` 按类型取发送器；Spring Boot 2.7 的邮件自动配置在缺少 `MailSender` Bean 时才生效。直接注册新发送器可能导致旧默认发送器不创建，或旧业务取得错误客户端。若改为多 Bean，必须显式构建和绑定新旧发送器，并证明旧配置行为等效。

新账号配置缺失、密码错误、招聘功能关闭或发信失败，不得导致旧邮件业务停止；不得回退使用旧邮箱或旧飞书群。

### 6.5 邮件内容

主题建议包含环境、Xianova 招聘、岗位、姓名和申请编号。正文包含申请字段、岗位快照、提交时间和申请编号；附件使用安全文件名。`Reply-To` 使用经过校验的候选人邮箱，From 与 SMTP 账号关系符合邮箱服务商要求。

“SMTP 已受理”不等于收件箱送达或 HR 已阅读，不记录没有可靠依据的 `DELIVERED` 状态。

## 7. 记录持久化

建议复用 MySQL，新增两张业务表。表名和字段类型在后端设计阶段按项目规范定稿。

### 7.1 应聘申请

建议表：`recruitment_application`。

| 字段组 | 内容 |
| --- | --- |
| 标识 | 内部主键、对外申请编号、请求编号、站点、幂等标识及请求内容指纹。 |
| 岗位 | 岗位编号、提交时名称及必要版本快照。 |
| 候选人 | 姓名、邮箱、区号与手机号、补充说明及最终确认字段。 |
| 附件元信息 | 原文件名、安全文件名、大小、类型，可选摘要；不保存文件内容或公开 URL。 |
| 告知 | 确认记录、告知文本版本、确认时间。 |
| 状态和时间 | 登记状态、邮件状态、补传要求、创建与更新时间。 |

### 7.2 通知尝试

建议表：`recruitment_notification_attempt`，关联申请记录。

保存尝试次数、渠道、发送账号标识、受控收件人快照、开始和结束时间、结果、脱敏错误摘要及可获得的邮件 Message-ID。保存 SMTP 密钥、完整 MIME 邮件或附件二进制作为变相长期文件副本。

### 7.3 邮件状态建议

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 记录已提交，尚未发信。 |
| `SENDING` | 发信中，需要控制同申请并发。 |
| `SMTP_ACCEPTED` | 发信服务器已受理。 |
| `FAILED` | 已知发送失败；是否可重试取决于附件是否仍可用。 |
| `UNKNOWN` | 超时或中断导致受理结果不能确认，先核查再处理。 |
| `REUPLOAD_REQUIRED` | 附件已不可恢复且未确认投递完成，需要补传。 |

申请及初始通知记录先提交事务，再发信，结果独立更新；不让 SMTP 网络等待占用数据库长事务。处理进程中断、更新结果失败的记录应可排查，不自动视为成功。

数据库结构用新增 Flyway 迁移管理，遵守现有 `db/migration/README.md`，不得修改已执行迁移、重建数据库或以调整基线掩盖结构差异。

## 8. 安全及运行边界

- 为招聘路径独立配置 CORS、限流命名空间、超时和并发上限；不覆盖旧路径配置。CORS 不是防刷认证。
- 新提交路径精确免登录；内部查询保持鉴权，不能通过申请编号任意读取他人信息。
- 校验大小、允许类型及内容特征，拒绝不必要的压缩包、可执行文件和宏文档；文件扫描方案上线前结合现有能力确认。
- 临时文件随机命名，位于非静态目录，覆盖成功、异常及崩溃遗留清理，避免删除正在发送的文件。
- 同步配置反向代理和 Spring multipart 上限；不为招聘改动全局限制而意外影响旧业务。
- 浏览器直传 Java 后端。若改为经 Vercel 函数中转，重新评估上传大小限制。
- 日志只记录追踪信息及脱敏错误，不记录完整简历、凭据和完整申请正文。
- HR 确认招聘隐私告知、处理地区、记录与邮箱附件保存期限、删除渠道及负责人。
- 监控登记量、通知受理量、失败及未知状态、限流拒绝和临时文件清理异常。

## 10. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 页面浏览 | 桌面和手机可完成列表、详情和申请；无效或关闭岗位不能提交。 |
| A02 | 有效申请 | 申请及通知尝试入库；正确收件人收到岗位、信息和可打开的附件。 |
| A03 | 校验 | 缺项、非法文件、超大文件被服务端拦截，页面给出明确提示。 |
| A04 | 幂等 | 同次重复请求不重复建记录，不对已确认受理的申请重复发信；未知状态不盲目重发。 |
| A05 | 入库异常 | 不发信、不显示登记成功，重试可恢复。 |
| A06 | 发信异常 | 保留原记录和状态，候选人获得可操作的补传或重试提示。 |
| A07 | 配置隔离 | 新旧业务各用自身账号和收件人，招聘关闭或错误配置不影响旧业务。 |
| A08 | 旧业务回归 | 原接口格式、邮件目标及飞书行为保持既有契约。 |
| A09 | 环境切换 | 本地和开发使用测试发件账号，生产使用 HR 配置且不回退测试账号。 |
| A10 | 权限与文件清理 | 不公开他人记录或简历链接；临时文件在成功、失败及异常后可清理。 |
| A11 | 范围控制 | “联系我们”未接入新后端；未混入解析、人才库或完整管理后台。 |
