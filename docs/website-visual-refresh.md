### 首帧闪屏修复

- 原因：上一版服务器返回首页时没有开场层，客户端 hydration 后才创建动画，导致正文先显示再被动画覆盖。
- 修复：服务器输出 `pending` 开场壳层，在 head 中以同步脚本和关键样式提前决定遮挡；客户端动画准备好后再接管。壳层内的动画先暂停，接管后开始播放，仍保留约 1.65 秒渐显、2.2 秒落位、2.4 秒结束的节奏，不增加跳过入口。
- 已看过开场的标签页不启用首帧遮挡；关闭或阻止脚本时默认显示正文。应用脚本失败时最多等待 8 秒即解除壳层，脚本稍后恢复也不再补播，避免首页出现后再次被开场覆盖。
- 新增回归检查 `node --test scripts/brand-opening-boot.test.mjs`，6 项通过：首次遮挡、重复／内页／锚点／历史入口、减少动态效果／后台标签页、存储不可用、超时解除遮挡和超时不干扰已启动或已结束的动画。
- 浏览器验证：使用生产构建 HTML 临时隔离应用脚本，确认 `pending` 时正文 `visibility:hidden`、开场显示；应用未启动时能自动解除遮挡。保留 HTML 而移除脚本时正文直接可见。正常首次访问与刷新无 hydration 警告，结束后正文可见、滚动与 `inert` 清理。390×844 手机首次完整导航进入首页时直接处于开场，结束后无横向溢出；控制台无警告或错误。
- 最终构建、类型检查、构建内置 lint 与 16 页静态生成通过，日志为 `runtime-logs/particle-home/build-opening-first-paint.log`。截图为同目录下 `first-paint-before-hydration.png`、`first-paint-mobile-opening.png`。临时验证服务已停止，本地首页继续运行；没有提交、推送或部署。
